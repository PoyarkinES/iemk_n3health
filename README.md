# EMK integration

Решение для интеграции медицинской информационной системы с сервисами PIX и EMK: выбирает случаи лечения, проверяет необходимые условия, формирует DTO документов и отправляет данные во внешние сервисы.

> **Важно перед публикацией репозитория.** В текущем репозитории отслеживается `EmkService/SmoSettings.xml` с рабочими данными о медицинских работниках. Не публикуйте репозиторий и не переносите этот файл в общедоступный пример без проверки и очистки. Простого удаления файла из новой версии недостаточно, если данные остались в истории Git.

## Состав решения

| Проект | Назначение |
| --- | --- |
| `Emk` | Основная библиотека: бизнес-процессы отправки, сервисы PIX/EMK, доступ к ODBC-БД, настройки и документы |
| `EmkCda` | Модели и генерация CDA-документов |
| `EmkConfig` | Настольное приложение с DI-композицией и формами, вызывающими Application use cases |
| `EmkWinService` | Windows-служба, запускающая `ServiceRunner` и Application use case отправки |
| `EmkTests` | Модульные тесты бизнес-логики и генерации CDA |

Решение `Emk.sln` использует классические проекты .NET Framework, а не SDK-style проекты. Подробности структуры и потоков данных приведены в [обзоре архитектуры](docs/architecture.md).

## Быстрый старт для разработчика

### Требования

- Windows и Visual Studio 2022 17.8+ с поддержкой .NET Framework 4.6.1 и классических `.csproj`.
- Компилятор C# 12 или новее: в проекте используются современные конструкции языка, хотя целевая платформа — .NET Framework.
- Восстановленные NuGet-пакеты из `packages.config`.
- Для запуска интеграции — настроенный ODBC-драйвер и DSN для базы данных, а также доступ к рабочим конечным точкам PIX/EMK.

Сборка и модульные тесты не требуют подключения к рабочей базе или внешним WCF-сервисам. Внешние зависимости тестируются через заглушки.

### Сборка

В Developer PowerShell for Visual Studio из корня репозитория:

```powershell
dotnet build .\Emk.sln --no-restore --verbosity minimal
```

Если сборка сообщает об отсутствующих пакетах, восстановите NuGet-пакеты средствами Visual Studio, затем повторите команду.

### Тесты

После успешной сборки запустите тестовую сборку через VSTest:

```powershell
vstest.console.exe .\EmkTests\bin\Debug\EmkTests.dll
```

Также можно запустить тесты проекта `EmkTests` из Test Explorer Visual Studio. `dotnet test` для этого старого проекта может не обнаружить MSTest корректно.

### Настройка окружения

Перед локальным запуском проверьте конфигурацию и замените значения на параметры своего окружения:

- `EmkService/EmkDb.config` — общая строка подключения ODBC; конфигурации приложений ссылаются на неё через `configSource`.
- `EmkConfig/App.config` и `EmkWinService/App.config` — прикладные параметры запуска.
- `SmoSettings.xml` — настройки врача и значения по умолчанию; файл должен находиться рядом с `Emk.dll` во время запуска.
- Адреса, идентификаторы организации и прочие параметры интеграции должны соответствовать целевому стенду.

Не добавляйте в Git пароли, реальные строки подключения, рабочие токены, персональные или медицинские данные. Для настройки используйте локальные конфиги; перед передачей конфигурации проверяйте и её содержимое, и историю репозитория. Дополнительные инструкции — в [руководстве разработчика](docs/development.md).

### Новые точки входа

`EmkConfig.Program.Main()` и `EmkWinService.Program.Main()` собирают DI-контейнер из регистраций Application и Infrastructure. Строка подключения берётся из `ConnectionStrings["EmkDb"]`; оба `App.config` подключают общий `EmkService/EmkDb.config` через `configSource`, поэтому этот файл должен быть развёрнут рядом с приложением.

В `EmkConfig` отправка и обновление проходят через `ISendPatientDataUseCase` и `IUpdatePatientDataUseCase`. Windows-служба запускает `ServiceRunner`, который проверяет настройки и повторяет цикл отправки каждые пять минут. Настройки подключения и адреса PIX/EMK остаются в конфигурации конкретной среды; локальные значения и секреты не добавляйте в Git.

Проект `Emk` и его старые формы/сервисы сохранены для обратной совместимости. Новый `EmkConfig` использует собственные формы для операций Application слоя; экран редактирования прежних настроек пока делегируется существующей форме `Emk`.

## Состояние и ограничения

- Проект нацелен на .NET Framework 4.6.1; перенос на современный .NET потребует отдельной миграции.
- Требуются установленный ODBC-драйвер/DSN и доступность WCF-сервисов для сквозного запуска.
- Создание документов `DocAppointedMedication` и `DocControlCardDispensaryObservation`, а также методы `EmkSendingServiceExt` пока не реализованы и выбрасывают `NotImplementedException`.
- Для восстановления бизнес-процессов и ограничений окружения см. [архитектуру](docs/architecture.md) и [разработку](docs/development.md).

## Правила изменений

- Не редактируйте сгенерированные прокси в `Emk/Connected Services/**/Reference.cs` вручную.
- Сохраняйте независимость тестов от рабочей БД и внешних сервисов.
- Проверяйте каждую функциональную правку сборкой и целевыми тестами.
- Не публикуйте конфигурацию и данные рабочего окружения.
