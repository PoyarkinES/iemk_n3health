# Руководство разработчика

## Рабочее окружение

Решение состоит из классических проектов Visual Studio и ориентировано на .NET Framework 4.6.1. Для сборки нужен Windows, Visual Studio 2022 17.8+ (или совместимый MSBuild) с соответствующими targeting packs и компилятором C# 12 или новее. В репозитории не следует фиксировать папки `bin`, `obj`, `packages` или пользовательские файлы IDE.

Интеграционный запуск дополнительно требует:

- ODBC-драйвер, DSN и сетевой/файловый доступ к базе МИС;
- доступность конечных точек PIX и EMK;
- конфигурацию конкретной организации и каталоги документов;
- `SmoSettings.xml` рядом с исполняемым расположением `Emk.dll`.

## Команды

Из корня репозитория в Developer PowerShell for Visual Studio:

```powershell
dotnet build .\Emk.sln --no-restore --verbosity minimal
vstest.console.exe .\EmkTests\bin\Debug\EmkTests.dll
```

Если NuGet-пакеты ещё не восстановлены, сначала выполните восстановление в Visual Studio для решения. В тестовой среде доступен VSTest; `dotnet test` не является надёжным запускателем для текущего формата MSTest-проекта.

## Работа с конфигурацией и данными

- Не добавляйте в коммиты реальные пароли, рабочие токены, строки подключения с секретами, персональные данные врачей/пациентов или реальные документы.
- `EmkService/EmkDb.config` содержит шаблон DSN; заменяйте его для локального/тестового окружения, не помещая секреты в репозиторий.
- `EmkService/SmoSettings.xml` сейчас отслеживается Git. Перед публикацией репозитория или распространением его копий проверьте файл и историю на реальные данные; при необходимости подготовьте безопасный шаблон отдельно.
- Тесты должны использовать поддельные репозитории и WCF-клиенты. Не привязывайте unit-тесты к рабочей базе или сервисам.

## Правила изменения кода

1. Сначала найдите существующие интерфейсы, адаптеры и тестовые заглушки; по возможности расширяйте их вместо введения параллельной инфраструктуры.
2. Не меняйте вручную сгенерированные файлы `Emk/Connected Services/**/Reference.cs` и связанные метаданные прокси.
3. Асинхронные операции должны возвращать и ожидать `Task`; не добавляйте `.Result`, `.Wait()` или блокирующие ожидания.
4. Сохраняйте существующее поведение интеграционных контрактов, пока изменение явно не покрыто требованиями и тестами.
5. Для исправления поведения добавляйте регрессионный тест, затем собирайте решение и запускайте целевые тесты.
6. Не удаляйте и не переписывайте локальные конфигурации и пользовательские данные без отдельного согласования.

## Развёртывание

Сборка не является проверкой развёртывания. Перед выпуском отдельно проверьте конфиги `EmkConfig` и `EmkWinService`, наличие общей ODBC-конфигурации, DSN, `SmoSettings.xml`, каталогов файлов и доступность WCF-адресов на целевом стенде. Не публикуйте журналы или диагностические дампы с персональными данными.
