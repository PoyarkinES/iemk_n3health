# Инструкции для автоматизированных изменений

## Контекст решения

- Это классическое решение Visual Studio `Emk.sln` на .NET Framework 4.6.1, не SDK-style.
- Основные проекты: `Emk` (бизнес-логика/интеграция), `EmkCda` (CDA), `EmkConfig` (настольная настройка), `EmkWinService` (служба), `EmkTests` (MSTest).
- БД подключается через ODBC; PIX и EMK вызываются через WCF.
- Подробное устройство решения и команды разработки описаны в `README.md` и `docs/`.

## Обязательные ограничения

- Не редактировать вручную код и метаданные в `Emk/Connected Services/**`; это сгенерированные прокси.
- Не читать или записывать реальные БД/WCF в тестах. Использовать интерфейсы и поддельные зависимости.
- Не добавлять в Git локальные конфиги с реальными адресами/секретами, `SmoSettings.xml` с персональными данными, документы, логи или дампы.
- Не менять бизнес-семантику медицинских документов без требований; незавершённые типы перечислены в `docs/architecture.md`.
- Сохранять незакоммиченные изменения пользователя. Не выполнять push, пока пользователь явно не попросил.

## Проверка

Собирать решение из Developer PowerShell:

```powershell
dotnet build .\Emk.sln --no-restore --verbosity minimal
vstest.console.exe .\EmkTests\bin\Debug\EmkTests.dll
```

При изменении поведения добавить регрессионное покрытие. Не заявлять, что проверена интеграция с БД или внешними сервисами, если запускалась только сборка/unit-тесты.
